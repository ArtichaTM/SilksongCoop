# Audit 2.01: Tut_01, Tut_01b, Tut_02, Tut_03, Tut_04, Tut_05

Reading guide. Verdict: sure / maybe / no = does coop need to handle it. Tut is the first area in scene order, so it also owns most generic C# types; trivial plumbing is grouped. Two facts matter across the whole slice:
- Triggers written as `Trigger2dEvent collideTag="Player"` or `OnTriggerEnter2D` with a Player check only ever see the LOCAL hero. The partner's Hornet has no collider, so reminders, cam locks, start regions, battle triggers and bridge impacts never fire for the partner.
- Rooms are built from variants chosen at load by `TestGameObjectActivator` (PlayerData, quests, entry gate): "Black Thread States / Normal World vs Black Thread World" (PD blackThreadWorld) and "States / Intro Scene vs Outro Scene" (Tut_04). Players with different PlayerData load different variants of the same room.
Notes written or used: BattleScene, HealthManager, DamageHero, TransitionPoint, CameraLockArea, Breakable, TestGameObjectActivator, BlackThreadState, Remasker, AlertRange, BatchKillEvent, RestBench, HazardRespawnTrigger, PersistentBoolItem, CheckHeroPerformanceRegion, DistanceFlyV2, EnemySingControl, WalkerV2.

## Summary

Events that should pull the partner to the player who triggered them (or at least lock both), each with a reason:
1. Moss Mother fight (Tut_03.1 and Tut_03.2): the arena starts only for the local hero, closes gates and camlocks only in that game, and its attacks (DistanceFlyV2, roar stun, RNG drops) target one hero. Pull the partner in on BATTLE START, lock both, and send BATTLE END.
2. Mossbone Mother Ambient (Tut_02.2): hero-targeting mini-boss, Black Thread World only; same handling.
3. Tutorial Intro Cutscene (Tut_01.3): control lock and PD write on a new game; pull or hold the partner only if you want both to see it, otherwise let each run their own.
4. Snail shaman first meeting (Tut_04.1) and Hornet ritual/outro (Tut_04.6, Tut_04.7): forced dialogue and cutscene control on the local hero; decide freeze vs free.
5. Crest shrine and memory scenes (Tut_04.4, Tut_05.1): the local hero is sent to a different (solo) scene and returns via door_memoryEnd; decide whether the partner waits, follows, or has their Hornet hidden, and whether crest unlock is shared.

Non-negotiable syncs (sure, because only the actor's game changes otherwise): one-time route blockers and loot (Fixer Bridge break, Moss Vine Clusters, One Way VineWall, Bone Chest, shell shard fossil, fruit, unique item pickup), the Set Tutorial Completed trigger (PD completedTutorial), and enemy FSM state/death for Bone Thumper, MossBone Fly, Bone Roller, MossBone Crawler and the boss with its crawlers and stalactites.

Gaps and cross-cutting issues:
- Local-hero-only triggers: every `Trigger2dEvent Player` and `AlertRange` that is not an enemy (chest "Hero Region", vine "Hit Cancel Range", Song gate "Leave Range", camlocks, reminders, start/end regions) never sees the partner's Hornet.
- Needolin: Song_Gate_set, Mr Mushroom, cocoon sway and the boss Sing all use the local needolin only; decide whether the partner's needolin counts.
- Scene variants by PlayerData (TestGameObjectActivator, BlackThreadState): players with different blackThreadWorld, completedTutorial or quest state load different rooms, bosses and NPCs; pick one deciding game (host or room owner) for these flags.
- Boss RNG (SLAM or SWOOP, rock or crawler, stalactite X) must come from the owner.
- Per-player by design (do not sync): hazard and death respawn, benches, map/area titles, music, camera.
